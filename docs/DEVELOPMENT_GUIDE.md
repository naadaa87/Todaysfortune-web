# 오늘의사주 후속 개발 가이드

## 1. 현재 구조를 유지하면서 확장하는 권장 순서

### 1단계 — 정적 홈페이지와 콘텐츠 운영
- 현재 HTML/CSS/JS를 그대로 배포
- 실제 도메인, 사업자 정보, 이용약관, 개인정보처리방침 반영
- 검색엔진 등록 및 분석 도구 연결
- 명리 콘텐츠를 주 1~2회 업데이트

### 2단계 — 회원가입과 데이터베이스
권장 구성 예시:
- 프론트엔드: Next.js 또는 React
- API: Cloudflare Workers
- 데이터베이스: Cloudflare D1 또는 관리형 PostgreSQL
- 인증: Clerk, Auth0, Supabase Auth 또는 자체 OAuth
- 파일 저장: Cloudflare R2

회원 데이터와 사주 데이터는 분리하고, 출생 정보는 암호화·접근 통제·삭제 기능을 갖춰야 합니다.

### 3단계 — 만세력 및 명리 해석 엔진
분리 권장:
1. 달력·절기·시간대 계산 모듈
2. 사주팔자·대운 산출 모듈
3. 구조화된 해석 규칙 모듈
4. 자연어 리포트 생성 모듈
5. 전문가 검수 워크플로

AI가 계산식을 대신하게 하지 말고, 검증된 계산 결과를 AI가 읽기 쉬운 문장으로 정리하도록 역할을 분리하는 편이 안전합니다.

### 4단계 — 결제와 디지털 콘텐츠
- 국내 PG: 토스페이먼츠, KG이니시스 등 비교
- 결제 완료 후 주문·리포트 생성 상태를 별도 테이블로 관리
- 생성 전/생성 후 환불 기준을 명확히 표시
- 전문가 검수 상품은 예상 제공 시간을 결제 전에 표시

### 5단계 — 관계·커뮤니티 기능
- 초대받은 사람이 직접 정보 입력
- 비교 분석 동의와 공개 범위를 분리
- 링크 만료, 차단, 동의 철회, 데이터 삭제 지원
- 공개 커뮤니티에는 출생 정보가 노출되지 않도록 설계

### 6단계 — Android/iOS 앱
웹 API를 먼저 안정화한 후 앱을 만듭니다.
- 초기: React Native 또는 Flutter
- 푸시: 오늘의 흐름, 밤의 회고, 친구 초대 알림
- 웹과 앱에서 동일한 회원·결제·분석 데이터를 사용

## 2. 핵심 데이터 모델 예시

- users: 회원 기본 정보
- birth_profiles: 출생 정보와 계산 설정
- charts: 계산된 원국·대운 데이터
- reports: 상품별 분석 결과
- relationships: 2인/그룹 관계와 동의 상태
- invitations: 초대 토큰과 만료 시간
- orders: 결제·환불 상태
- journal_entries: 운의 기록
- content_posts: 명리 지식 콘텐츠
- consent_logs: 개인정보 및 관계 비교 동의 기록

## 3. 관리자 화면 필수 기능

- 회원 및 출생 정보 접근 권한 관리
- 분석 생성 실패 재처리
- 주문·환불·쿠폰 관리
- 전문가 검수 배정 및 작업 상태
- 콘텐츠 작성·예약 발행
- 신고·차단·초대 링크 폐기
- 테마별 배너 및 이벤트 관리
- 전환율, 재방문율, 공유율 대시보드

## 4. 우선 측정할 지표

- 방문 → 무료 분석 시작률
- 입력 시작 → 완료율
- 무료 결과 → 유료 결제 전환율
- 관계 초대 발송률과 수락률
- 결과 공유율
- 1일·7일·30일 재방문율
- 리포트 생성 실패율
- 환불률과 CS 사유

## 5. 브랜드·콘텐츠 운영 원칙

- 공포와 불안을 결제 유도에 사용하지 않음
- 사망, 질병, 이혼, 파산 등을 확정적으로 예언하지 않음
- 의료·법률·투자·채용 판단을 대신하지 않음
- 사주명리와 주역을 하나의 계산 체계처럼 혼합하지 않음
- 자동 생성 문장은 명리 전문가의 용어·논리 검수 기준을 통과하도록 관리
